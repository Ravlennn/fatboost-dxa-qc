## Реализовано

| Требование | Реализация / проверка |

| Локальный CLI | `dxaqc -i ... -o ...`, реальные веса по умолчанию |

## Что нельзя считать закрытым

- **Независимый тест.** Старый holdout уже использован. OOF подходит для разработки; окончательные метрики — на новых закрытых данных организатора.
- **Редкие причины.** По некоторым типам всего 6–10 положительных изображений; их головы не обеспечивают надёжных объяснений. Указаны macro F1 и support, ошибки не скрыты.
- **Неизвестная причина.** `quality_unspecified` сохраняет смысл бинарного решения без выдумывания причины. Этот дополнительный код нужно согласовать с организаторами, если они требуют закрытый словарь ровно из пяти типов.
- **Проекция и неизвестная анатомия.** Модель различает только три обученные категории. Отдельного валидированного распознавания AP/lateral/других проекций и неизвестного изображения пока нет. Новый аппарат/вид может ошибочно попасть в известную категорию.
- **Физическая геометрия.** В release есть ориентиры, оценка угла и полей в
  миллиметрах, а также DICOM Secondary Capture overlays. Но эти измерения не
  прошли независимую клиническую калибровку; они служат объяснением модели, а
  не сертифицированным измерительным протоколом. DICOM SR не реализован.
- **Обобщение.** Нет проверки на другом центре/аппарате и связи пациентов между исследованиями. REVIEW — техническое предупреждение; его клиническая безопасность не валидирована.
- **Финальная презентация.** В комплекте сценарий и структура доклада, не готовые PPTX-слайды.

## Инженерные проверки

Результаты фактических запусков фиксируются в конце этого документа после сборки. Полная матрица автоматизированных тестов — `tests/test_release_cli.py`, плюс прежние тесты backbone/ROI. Синтетические тесты не подтверждают диагностическую точность; три DICOM организатора без меток проверяют только интеграцию.

### Измеренные проверки от 2026-09-19

- 35 автоматических тестов: 34 прошли в sandbox, localhost-транспорт отдельно успешно проверен с разрешённым bind. Проверяются DICOM/MONOCHROME1, UID, дубликаты, ZIP, ошибки отдельных файлов, контракт, XLSX-строки, пороги, отсутствие silent fallback, защита исходных DICOM и ограничение квадратного дополнения.
- Полная parity-проверка: 150/150 hip-изображений и 450 вероятностей. Все тензоры побитно совпали с исторической обучающей предобработкой, максимальное расхождение CPU и сохранённых OOF = 2.3842×10⁻⁶ при допуске 10⁻⁴.
- Один пограничный quality-score совпадал с exact OOF-порогом. В поставке используются середины соседних score-интервалов: OOF-классы неизменны, минимальный отступ до порога превышает измеренную ошибку CPU/MPS для всех трёх голов. Это не улучшение статистической метрики.
- Локальный CPU smoke: три файла организатора, 3 Success / 0 Failure, 2 исследования; около 10.15 с вместе с подготовкой модели. Это технические примеры без экспертных меток.
- Docker Linux arm64 CPU, сеть отключена, два CPU: те же три файла, 3 Success, около 5.04 с вместе с подготовкой модели. CSV совпал с локальным выводом по всем полям кроме времени.
- Запуск через `run-copy.sh` проверен с XLSX: около 5.14 с, 3 Success. В местном Docker context `avito` bind-mount запуск зависал до создания контейнера; его процесс остановлен. Переносимый вариант с `docker cp` работает. Сам алгоритм отдельно проверен в read-only контейнере через stdin-harness без host mounts.

Логи и численные протоколы остаются в `outputs/release_checks/`. Время этих трёх примеров не доказывает верхнюю границу для любых файлов; производительность на H200 и полном закрытом наборе не измерена.

Финальный Linux x86_64 образ также обработал 3/3 DICOM без ошибок под эмуляцией на Apple Silicon. Полное время с подготовкой: 414.7 с. Результаты CSV совпали с arm64 по всем полям, кроме времени: True. Из-за эмуляции и недоступного NNPACK это время не является измерением скорости на целевом Linux/H200. Образ сохранён для офлайн переноса: `outputs/dist/dxaqc-image-linux-amd64.tar`. Машинный протокол — `docs/ACCEPTANCE.json`.
