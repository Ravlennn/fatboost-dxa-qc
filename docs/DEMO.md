# Сценарий демонстрации

Около 7 минут. Данные для показа — три снимка организатора «Для теста» (позвоночник, правое и левое бедро) и «грязный» архив из синтетики.

1. **Локальный запуск.** `./scripts/run-ui.sh` — контейнер только для чтения, порт открыт лишь на 127.0.0.1, внешних запросов нет; открыть `http://127.0.0.1:8080/`. Коротко: всё локально, веса проверяются по SHA-256 (`dxaqc doctor`).
2. **Загрузка пакета.** Перетащить ZIP. Строки появляются по мере анализа, счётчики «Норма / Брак / Ошибки». Повреждённый файл даёт строку «Ошибка» с причиной, пакет продолжается.
3. **Позвоночник.** CR000000_ПОП: уровни L1–L4, наклон 2,6° (норма), поля кадра в мм, нарушение «Присутствуют посторонние предметы» — косточки бюстгальтера подсвечены. Шторкой «Сравнить» показать чистый снимок.
4. **Бедро.** CR000000_ППОБ: рамка ROI с полями, ось шейки, малый вертел выступает на 10,2 мм — «Некорректная укладка» (ротация). Связать с рис. 5 ТЗ.
5. **Коррекция специалистом.** «Исправить»: сдвинуть верх рамки ROI — миллиметры меняются сразу, после отпускания модель пересчитывает критерии. На карточке критерия поставить «Норма» вопреки модели, «Подтвердить». Счётчик «Проверено» растёт.
6. **Выгрузки.** CSV/XLSX по форме ТЗ (тексты организатора, `quality_prob`); архив DICOM SR — у проверенного снимка флаг `VERIFIED`, заключение модели сохранено отдельной строкой. «Исправления» — JSON для дообучения.
7. **Пакетный режим.** `dxaqc -i studies.zip -o result.xlsx --sr sr.zip --overlays overlays.zip`; HTTP `POST /v1/batch`.
8. **Метрики и ограничения.** F1 0.675 [0.57–0.77], ROC-AUC 0.828 при полной изоляции фолдов; скорость и системные требования; ограничения — мало разметки редких причин, один источник данных, потолок согласованности разметки по ротации бедра.
