# Развёртывание и API

## Окружение

Python 3.12; фактические версии research-окружения фиксирует `uv.lock`. CPU runtime: `requirements-runtime.txt`, PyTorch 2.14.0 CPU и torchvision 0.29.0 CPU. Официальный индекс CPU wheels: https://download.pytorch.org/whl/cpu/. Docker base: `python:3.12.12-slim-bookworm` (точная версия; digest готового образа сохраняется в отчёте сборки).

Практический минимум: 4 GiB доступной RAM для пакета небольших DXA, два CPU-потока, около 0.6 GB для весов плюс зависимости. Большие ZIP требуют дополнительного временного места. Лимиты контейнера можно изменить в `scripts/run.sh`; это не влияет на пороги модели. H200 не требуется для базового инференса. Скорость на H200 не измерена.

## Комплект поставки

- исходный код, Dockerfile, закреплённые зависимости, build/run;
- `models/release/manifest.json` и файлы, перечисленные в нём;
- документация и протокол проверки;
- метрики без исходных DICOM. Данные для обучения в релиз не включаются.

`dxaqc doctor --model-dir <directory>` проверяет SHA-256 каждого файла и структуру manifest. Он не доказывает качество модели и не выполняет forward. Веса загружаются через `torch.load(weights_only=True)`; линейные головы — числовой JSON. Joblib/pickle в основном runtime не используется.

Сборка требует интернета для установки пакетов. После сборки `scripts/run.sh` отключает сеть. Для переноса готового образа на полностью закрытую машину:

```sh
docker save dxaqc:local -o dxaqc-image.tar
# На целевой машине:
docker load -i dxaqc-image.tar
./scripts/run.sh /absolute/data.zip /absolute/out/result.csv
```

На Apple Silicon локальная сборка обычно arm64. Для x86_64 заранее собрать `./scripts/build.sh --platform linux/amd64`; архитектура образа должна совпадать с целевой машиной. Сборка и тест на одной архитектуре не являются тестом другой.

## DICOM и пакет

Папка обходится рекурсивно; кроме служебных `.DS_Store`, `DICOMDIR`, `Thumbs.db`, `._*`, каждый файл получает строку. Ошибка одного файла не прекращает пакет. Для `.zip` извлечение идёт во временную папку и удаляется после обработки. Вложенные папки сохраняются в относительных путях. Вложенный архив не раскрывается рекурсивно и получит Failure как не-DICOM.

Максимумы: 10 000 файлов, 2 GiB суммарно распакованных данных ZIP, 512 MiB на файл, 4096 пикселей по каждой стороне, 25 миллионов декодированных отсчётов в одном DICOM. Traversal (`../`), абсолютные пути, symlink, повторные имена и зашифрованные ZIP отклоняются как ошибка пакета. Для настоящих DXA ограничение значительно выше обычного размера.

Чтение: decompression через pydicom/pylibjpeg, slope/intercept, MONOCHROME1 inversion, min-max в uint8. Константный кадр — Failure. В многокадровом DICOM берётся первый кадр с явным предупреждением: такие данные требуют проверки. RGB переводится в среднее каналов; перенос на цветные отчёты не валидирован.

Недостающие UID заменяются детерминированными `2.25.*`: image — по пикселям, study — по логической папке внутри пакета. Это технические идентификаторы, не восстановленные настоящие DICOM UID. Результат не зависит от случайного имени временной папки ZIP. PatientName/PatientID в отчёт не экспортируются; пути и study/image UID по ТЗ сохраняются.

CSV/XLSX пишутся атомарно. Текстовые XLSX-ячейки не превращаются в формулы. CSV сохраняет исходные строки; открывайте неизвестные CSV как данные, без исполнения формул. `--path-mode dir` допускает несколько строк с одним путём исследования. Порядок файлов детерминирован, времена выполнения могут отличаться.

## HTTP API

```sh
.venv/bin/dxaqc serve --model-dir models/release --host 127.0.0.1 --port 8080 --threads 2
curl http://127.0.0.1:8080/health
curl -H 'Content-Type: application/zip' --data-binary @studies.zip http://127.0.0.1:8080/v1/batch > response.json
```

`POST /v1/batch`: тело ZIP, `Content-Length` обязательно, до 512 MiB сжатого архива; content type `application/zip`. Ответ 200 содержит все строки и статистику, включая ошибки отдельных файлов. 400 — повреждённый/небезопасный пакет; 413 — размер загрузки; 415 — неверный формат; 404 — неизвестный endpoint. Пустой допустимый ZIP возвращает пустые rows и `summary.status=empty`.

Процесс обслуживает пакеты последовательно, чтобы не создавать конкурирующие GPU/CPU задачи. Это локальный API без аутентификации; по умолчанию доступен только localhost. Для внешней инфраструктуры требуются собственный reverse proxy, аутентификация и ограничения доступа. Не включайте `--host 0.0.0.0` без такой настройки.


### Docker без доступа к папкам хоста

Для Docker context в VM без работающих bind mounts:

```sh
./scripts/run-copy.sh /absolute/studies.zip /absolute/results/new-result.xlsx
```

Скрипт копирует вход в отдельный локальный контейнер, запускает CLI без сети, возвращает отчёт/лог/сводку и удаляет контейнер. Исходный вход не изменяется. Выходные имена должны быть новыми, чтобы исключить перезапись исходных файлов. В этом варианте файловая система контейнера временная writable, все capabilities отключены; это отличается от read-only bind-варианта `run.sh`.

## Готовый образ для сдачи

Локально сохранён `outputs/dist/dxaqc-image-linux-amd64.tar` (образ `dxaqc:amd64`) с соседним SHA-256 файлом. В нём уже есть зависимости и выбранные веса; установка из сети не нужна:

```sh
docker load -i outputs/dist/dxaqc-image-linux-amd64.tar
DXAQC_IMAGE=dxaqc:amd64 ./scripts/run-copy.sh /absolute/studies.zip /absolute/out/new-result.csv
```

Для Linux с работающими bind mounts можно использовать `run.sh` с тем же `DXAQC_IMAGE`. Для arm64 создан локальный образ `dxaqc:local`. Запуск x86_64 на Apple Silicon использует эмуляцию, поэтому его время нельзя переносить на целевую машину.
