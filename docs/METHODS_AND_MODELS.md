# Методы и модели DXA QC

Дата фиксации: 2026-09-20. Этот документ объединяет описание слабой разметки
Arak, модели анатомических ориентиров, детектора артефактов позвоночника и
детектора малого вертела. Итоговые метрики всей сборки находятся в
[`FINAL_VALIDATION.md`](FINAL_VALIDATION.md), происхождение данных и лицензии —
в [`THIRD_PARTY.md`](THIRD_PARTY.md).

## 1. Общая схема

Релиз использует гибридный подход:

- CNN определяет область и даёт базовые scores качества;
- модель ориентиров переводит изображение в анатомические точки и измерения;
- детерминированные детекторы ищут проволоку/металл и профиль малого вертела;
- небольшие логистические головы объединяют заранее определённые признаки;
- все пороги выбираются только на обучающей части внешнего фолда при итоговой
  оценке.

Такой дизайн выбран из-за малого числа размеченных нарушений: от 6 до 41
положительного кадра на задачу. Большие модели и широкие переборы на этом объёме
данных оказались менее устойчивыми, чем анатомически привязанные признаки.

## 2. Слабая анатомическая разметка Arak

Источник — публичное зеркало набора Arak Bone Densitometry Center:

- [статья авторов](https://www.medrxiv.org/content/10.1101/2025.01.25.24319689v1.full);
- [зеркало Kaggle](https://www.kaggle.com/datasets/tommyngx/arak-bone-densitometry-center).

Архив содержит 4020 PNG-рендеров GE Lunar и таблицу на 3643 записи. Это не
исходные DICOM и не QC-разметка. Поверх изображений нанесены линии анализа со
значением пикселя 64. Скрипт `scripts/parse_arak_overlays.py` извлекает их как
слабые метки, удаляет линии inpainting-ом и инвертирует яркость под конвенцию
проекта.

```sh
uv run python scripts/parse_arak_overlays.py
```

Результат полного разбора:

| Вид | Разобрано | Не разобрано |
|---|---:|---:|
| Бедро | 2186 | 56 |
| Позвоночник AP | 938 | 161 |
| Предплечье | — | 179 |
| Боковая проекция / VFA | — | 309 |
| Не распознано | — | 191 |

Получено 3711 очищенных изображений. Для группового разбиения используется
`patient_key` из префикса имени; случайное разбиение по файлам запрещено.
Разметка отражает решение ПО/оператора Lunar, а не экспертный эталон. Условия
зеркала указаны как CC BY-NC 4.0, однако цепочка разрешений зеркала не
подтверждена авторами; данные и производные веса нельзя считать пригодными для
коммерческого распространения без отдельного согласования.

## 3. Модель анатомических ориентиров

`src/dxaqc/landmarks.py` содержит ConvNeXt-Tiny + FPN с heatmap-выходом шага 4
на входе 256×256. Модель предсказывает 12 каналов:

- бедро: четыре середины сторон ROI, центр шейки и две точки оси шейки;
- позвоночник: верх L1, границы L1/L2, L2/L3, L3/L4 и низ L4.

Обучение (`scripts/train_landmarks.py`): 2473 train, 335 validation и 315 test
изображений с разделением по пациентам, 30 эпох AdamW + OneCycle. На отложенных
пациентах Arak медианная ошибка точки — 1.9 px, центра шейки — 2.3 px, угла оси
шейки — 1.3°, наклона L1→L4 — 0.39°. Это точность относительно слабой разметки
Lunar, не относительно врача.

Перенос на 252 целевых снимка (`scripts/predict_landmarks_ours.py`) дал:

| Нарушение | Признак | AUC | Решение в релизе |
|---|---|---:|---|
| `spine_axis_tilt` | абсолютный наклон L1→L4 | 0.871 | голова по ориентирам |
| `spine_scan_range` | поля + видимость гребней | 0.871 | голова по ориентирам |
| `hip_roi_margins` | минимальный отступ ROI | 0.826 | CNN сильнее, измерение только объясняет |
| `hip_positioning` | угол шейки | 0.462 | угол не описывает ротацию |

При вложенном сравнении macro-F1 пяти причин вырос с 0.377 до 0.509. Политика
качества позвоночника затем была заменена на «брак, если найдена хотя бы одна
надёжная причина» и оценена заново в общем протоколе.

### Геометрические ограничения

Калибровка известными поворотами и обрезками (`scripts/calibrate_geometry.py`):

| Измерение | Средняя ошибка | 95% ошибок | Вывод |
|---|---:|---:|---|
| Наклон оси | 0.66° | 1.84° | в overlay выводится калиброванный угол |
| Нижнее поле ROI бедра | 2.2 мм | 7.6 мм | пригодно как объяснение |
| Запас над L1 | 6.6 мм | 29.8 мм | ненадёжен из-за переякоривания L1 |

Отдельной точки Th12 в v1 нет. Поэтому верхний запас нельзя заявлять как
надёжное прямое измерение; для scan range используется сигнал от гребней
подвздошных костей. Коэффициент наклона 0.921 применяется только к отображаемому
углу, а обученные головы получают исходное значение, чтобы не менять пороги.

## 4. Детектор артефактов позвоночника

`src/dxaqc/artifacts.py` ищет два типа объектов без обучения на метках качества:

1. тонкие вытянутые дуги проволоки вне полосы позвоночного столба;
2. небольшие яркие металлические компоненты с высоким локальным контрастом.

Ось L1→L4 и высота позвонка задают анатомический масштаб. Проволока выделяется
гребневым фильтром Гессе; компоненты фильтруются по длине, вытянутости и углу.
Металл выделяется по насыщению и контрасту, с более строгим порогом внутри
позвоночного столба.

| Вариант | AUC | AP | F1 | Чувствительность | Специфичность |
|---|---:|---:|---:|---:|---:|
| CNN | 0.742 | 0.574 | 0.522 | 0.35 | 1.00 |
| Детерминированный детектор | 0.774 | 0.649 | 0.733 | 0.65 | 0.98 |
| CNN + детектор | **0.840** | **0.684** | **0.774** | **0.71** | 0.98 |

Оценка получена на 99 снимках, из них 17 с артефактом. Детектор визуально
настраивался на тех же снимках при скрытых метках, поэтому результат остаётся
development-оценкой.

## 5. Малый вертел и ротация бедра

`src/dxaqc/lesser_trochanter.py` реализует детерминированный детектор профиля
малого вертела. После канонической ориентации по оси шейки алгоритм прослеживает
медиальный кортикальный край и измеряет выступ ткани в окне 21–57 мм ниже центра
шейки. Используются выступание, площадь, протяжённость и изгиб края.

Разработка велась по увеличенным листам 72 из 153 бёдер без показа меток
качества. Зафиксированный детектор затем оценён на пяти внешних фолдах.

| Задача | CNN AUC / F1 | Детектор AUC / F1 | Fusion AUC / F1 |
|---|---|---|---|
| `hip_positioning` | 0.779 / 0.615 | 0.826 / 0.627 | **0.836** / 0.545 |
| Качество бедра | 0.783 / 0.619 | 0.812 / 0.580 | **0.844** / **0.634** |

Зависимость нарушений от выступания U-образная: слишком малый профиль
соответствует переротации, слишком большой — недоротации. Ограничения:
эндопротезы, касание седалищной кости, зависимость окна от масштаба около
0.6 мм/px и отсутствие независимой внешней проверки.

## 6. Интеграция в runtime

Release bundle хранит веса и численные головы в `models/release/`; точный состав
задаёт `manifest.json`, а `dxaqc doctor` проверяет SHA-256. Для каждого снимка
runtime строит scores, принимает бинарное решение и при `--overlays` создаёт PNG
и DICOM Secondary Capture с ориентирами, углами и полями.

В релиз вошли:

- hip ConvNeXt для базовых scores;
- ориентиры v1 для позвоночника и геометрии;
- fusion CNN + детектор артефактов;
- fusion CNN + малый вертел для бедра;
- `quality_unspecified`, если бинарный брак найден, но причина не прошла порог.

Не вошли: DINOv2 linear probe, большие H100-модели, синтетический сегментатор,
TTA, буквальное правило полей ROI и ориентиры v2 на автоматических точках. Их
результаты и причины отказа собраны в
[`EXPERIMENT_RESULTS.md`](EXPERIMENT_RESULTS.md).

## 7. Воспроизведение методов

Полный повтор требует внешнего Arak, приватных DICOM, labels/folds, официальных
ImageNet checkpoints и сохранённых OOF. Канонический порядок описан в
[`TRAINING.md`](TRAINING.md). Базовые команды:

```sh
uv run python scripts/parse_arak_overlays.py
uv run python scripts/train_landmarks.py --device cpu
uv run python scripts/predict_landmarks_ours.py
uv run python scripts/run_landmark_fusion.py
uv run python scripts/eval_artifacts_lm.py
uv run python scripts/auto_label_lt.py
uv run python scripts/eval_lt_auto.py
```

Параметры конкретного сохранённого запуска и контрольные суммы находятся в
соответствующих каталогах `outputs/`. Они не входят в чистый Git-клон.
