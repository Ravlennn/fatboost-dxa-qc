# Предрегистрация: подтверждающий прогон модели C (вырез малого вертела)

Зафиксировано 2026-10-18 до первого запуска. Код, рецепт и критерий ниже не меняются после появления
результатов.

## Зачем

В [PREREG_NEW_MODELS.md](PREREG_NEW_MODELS.md) ветка C — ConvNeXt-Tiny 224 на вырезе 60 мм вокруг вершины
малого вертела — подняла AUC качества бедра 0.841 → 0.887, но 98.75% интервал (поправка на четыре ветки)
[−0.014; +0.120] задел ноль, и ветку не приняли. Там же записано, что включение C требует отдельной
подтверждающей проверки. Это она: одна гипотеза, заранее известная, без поправки на множественность.

## Что запускается

Тот же код и рецепт, что у ветки C (`scripts/train_hip_ltcrop_cnn.py` с параметрами по умолчанию: 224 px,
30 эпох, AdamW, OneCycle, те же 5 фолдов по исследованиям, 25 вложенных обучений), меняется только seed:
`--seed 1` вместо 0 (seed каждого фолда — seed + номер фолда). Вторая ступень, контроль и бутстрэп —
те же скрипты.

```sh
DEVICE=mps scripts/run_nested.sh scripts/train_hip_ltcrop_cnn.py outputs/ltcrop_cnn_s1 --seed 1
python scripts/eval_hip_nested.py --extra outputs/ltcrop_cnn_s1 --tag _C1
python scripts/compare_hip_arms.py _C1
```

## Критерий

- **Главная метрика:** ΔROC-AUC качества бедра (ветка − контроль `decisions_hip_nested.csv`) на тех же
  150 снимках бедра.
- **Интервал:** 95%, бутстрэп по исследованиям, 4000 повторов (`compare_hip_arms.py` с одной веткой).
- **Решение:** C подтверждена, только если интервал главной метрики целиком выше нуля. Иначе C остаётся
  отклонённой, результат записывается сюда же.
- **Только в отчёт:** ΔF1 качества бедра, F1 и AUC ротации, а также метрики всех областей по логике релиза
  с 18.10 (правило рамки ROI и «ближайшая причина», `scripts/per_type_metrics.py`).

## Ограничения

Выборка та же, что в исходной проверке: прогон проверяет устойчивость прироста к случайности обучения,
а не перенос на новые данные. Подтверждение не включает C в релиз само по себе: для релиза нужна финальная
модель C на всех фолдах и встраивание её оценки в `release_predictor.py` — отдельная работа.

## Результат (2026-10-18)

Все 21 прогон (`nested_base` с пятью фолдами и 20 вложенных) завершились без сбоев за 20 минут на Apple M4.
Сравнение — `compare_hip_arms.py _C1`, 95% интервал, бутстрэп по исследованиям, 4000 повторов.

| Метрика | Контроль | C, seed 1 | Δ [95% ДИ] |
|---|---|---|---|
| **AUC качества бедра (главная)** | 0.841 | 0.869 | **+0.029 [−0.021; +0.087]** |
| AUC ротации | 0.827 | 0.879 | +0.052 [+0.001; +0.110] |
| F1 качества бедра | 0.653 | 0.651 | −0.003 [−0.105; +0.109] |

**Решение: C не подтверждена**, интервал главной метрики задевает ноль. В исходном прогоне (seed 0) прирост
был +0.046, с другим seed — +0.029: заметная часть исходного прироста была случайностью обучения.

Только в отчёт, по логике релиза с 18.10 (правило рамки ROI и «ближайшая причина»): F1 качества всех областей
0.691 → 0.684, ROC-AUC 0.837 → 0.845, сбалансированная точность 0.790 → 0.779, F1 качества бедра 0.680 → 0.667,
AUC бедра 0.854 → 0.871. Вырез вертела немного улучшает ранжирование (AUC), но не решения (F1), а F1 и ROC-AUC
организатор называет главными метриками. Релиз не меняется.
