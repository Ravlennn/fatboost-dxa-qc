# Предрегистрация: функции потерь, устойчивые к шуму меток, для CNN бедра

Зафиксировано 2026-10-15 до первого запуска. Последняя непроверенная гипотеза из обзора функций потерь
(см. README, раздел «Эксперименты»: balanced logistic, BCE, focal, label smoothing, weighted BCE уже проверены).

## Гипотеза

Метки ротации и качества бедра шумные: три разных представления снимка упираются в один потолок
0.83–0.86 AUC. Функция потерь, ограничивающая вклад ошибочно размеченных кадров (GCE) или
асимметрично подавляющая лёгкие отрицательные примеры (ASL), повысит ROC-AUC качества бедра
полностью изолированного конвейера.

Ожидание до запуска: прироста нет. Тест закрывает гипотезу, а не подбирает рецепт.

## Ветки

Всё, кроме функции потерь, совпадает с контролем: ConvNeXt-Tiny, 384 px, 30 эпох, AdamW lr 1e-4,
batch 16, аугментации `full`, seed 0, MPS, те же пять фолдов, 25 вложенных обучений
(`scripts/run_hip_nested_local.sh`), тот же второй уровень (`scripts/eval_hip_nested.py`).

| Ветка | Функция потерь | Параметры |
|---|---|---|
| контроль | weighted BCE (текущий рецепт) | pos_weight по распространённости — готовые прогоны `outputs/hip_cnn/nested_*` |
| `_gce` | Generalized Cross Entropy, Zhang & Sabuncu 2018 | q = 0.7, тот же pos_weight |
| `_asl` | Asymmetric Loss, Ben-Baruch et al. 2021 | γ+ = 0, γ− = 4, clip = 0.05 |

Параметры — значения по умолчанию из статей, не подбираются.

## Конечные точки и критерий

- Главная: ΔROC-AUC качества бедра (ветка − контроль) на одних и тех же 150 кадрах.
- Вторичные (только отчёт): ΔROC-AUC ротации, ΔF1 качества бедра.
- Интервал — бутстрэп по исследованиям, 4000 повторов; поправка Бонферрони на две ветки: 97.5%.
- Ветка принимается, только если интервал главной конечной точки целиком выше нуля.
  Если проходят обе — берётся ветка с большей нижней границей.

Сравнение: `python scripts/compare_hip_arms.py _gce _asl`.
